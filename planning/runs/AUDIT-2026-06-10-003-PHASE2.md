### TASK-F-007: validate-status.ts gate dependency lookup bug

The script ran but produced 2 false-positive dependency errors:

```
[dependency] Task P1-T01 is DONE but depends on P0-GATE which is NOT_STARTED.
[dependency] Task P2-T01 is DONE but depends on P1-GATE which is NOT_STARTED.
```

**Root cause:** Line 88: `const depState = status.tasks[depId]` — when a task depends on a gate (e.g., `P0-GATE`), the lookup in `status.tasks` always returns `undefined` because gates live in `status.gates`. Both `P0-GATE` and `P1-GATE` were correctly set to `DONE` in `status.yaml`, but the script was looking in the wrong map.

**Before fix:** 28 errors (2 false-positive dependency + 26 legitimate reviewer)
**After fix:** 26 errors (only legitimate reviewer gaps remain)

## Design Decisions and Assumptions

### Dependency resolution order

Used `??` (nullish coalescing) so `status.tasks` takes priority, then falls back to `status.gates`. This handles the case where a task and gate share an ID without the behavior change of always checking both. In practice, task IDs and gate IDs use distinct naming conventions (`P0-T01` vs `P0-GATE`) so collisions don't occur.

### Why the `yaml` dependency is not added

The `yaml` package (`^2.9.0`) is already a dependency in `package.json` line 29. The script's import `import { parse as parseYaml } from 'yaml'` is correct and works. No dependency change was needed.
