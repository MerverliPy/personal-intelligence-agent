## Original design decisions

1. **Dependency inversion**: `Tracer` and `Meter` are no-op by default.
2. **AsyncLocalStorage for correlation**: Matches Node.js best practices.
3. **Sensitive field redaction at logger boundary**: Automatic redaction on every meta object.
4. **Case-insensitive field matching**: `SENSITIVE_LOG_FIELDS` entries stored lowercase.
5. **`[REDACTED]` marker**: Consistent with `@pia/config`.
6. **Child logger bindings at root level**: Structure for querying.

## AUDIT ADDENDUM (2026-06-10): FAILED_VERIFICATION

### Acceptance criterion #1: NOT MET

> "Every API request and worker job has a correlation identifier."

**Finding**: Correlation is established only at process startup. The `runWithCorrelation()` call in `apps/api/src/index.ts:40` wraps only the startup log message. The `runWithCorrelation()` call in `apps/worker/src/index.ts:37` wraps only the main boot sequence.

**Evidence of missing per-request correlation**:

- `apps/api/src/plugins/request-id.ts:14-19` — Sets Fastify's own `request.id` but never calls `runWithCorrelation()`. The `getCurrentCorrelationId()` function returns `undefined` during request handler execution.
- `packages/jobs/src/consumer.ts:190` — Sets `correlationId: record.id` on the `JobContext` object but never calls `runWithCorrelation()` to propagate the correlation context through `AsyncLocalStorage`. Handler log entries do not carry the correlation ID.

**Evidence of missing per-job correlation**:

- `packages/jobs/src/consumer.ts:196-234` — `processJob` invokes `handler.handle()` directly without wrapping in `runWithCorrelation()`. The correlation ID exists on the `JobContext` object but is not propagated into the logger's automatic context injection.

### Original criterion assessment correction

- AC-1: **FAIL** — Per-request and per-job correlation missing
- AC-2: PASS — Structured logs exclude sensitive fields (unchanged)
- AC-3: PASS — Telemetry can be disabled (unchanged)

### Required fixes

1. Wrap API request lifecycle in `runWithCorrelation()` with a correlation ID matching the request ID.
2. Wrap job handler execution in `runWithCorrelation()` with the job's correlation ID.
3. Add bounded inbound ID validation (max length, safe characters).
4. Add tests proving context isolation across concurrent requests and jobs.

## Security/privacy impact (unchanged)
