## Design decisions and assumptions

1. **Migration numbering**: Used `007` (not 006) because migration 006 was already consumed by `users_last_seen`. Migration 005's header comment referencing "006 — conversations" is outdated but left as-is.

2. **`sensitivity` on conversations**: Added `sensitivity sensitivity_class NOT NULL DEFAULT 'INTERNAL'` to the `conversations` table. The reference `schema.sql` omitted this column, but `docs/03_DATA_MODEL.md#9` explicitly requires conversations to carry sensitivity classification alongside sources, documents, memories, and tool connections.

3. **Type naming**: Used `PersistedMessage` for the DB entity to avoid collision with the model-gateway `Message` type in `@pia/ai`. The gateway `Message.role` uses `'system'|'user'|'assistant'|'tool'` while the DB uses `USER|ASSISTANT|SYSTEM_NOTE|TOOL`. Mapping is documented in the repository layer.

4. **Message immutability**: Only `createMessage()` is exposed. No `updateMessage()` or `deleteMessage()` functions exist. The `messages` table has no `status`, `updated_at`, or `deleted_at` column — it is truly append-only.

5. **Concurrency control**: `completeModelRun()` uses `WHERE status = 'STREAMING'` for optimistic concurrency. Two concurrent workers attempting to complete the same run will result in one success and one `ModelRunTransitionError`. No `version` column or `SELECT ... FOR UPDATE` is needed because the status check serves as the concurrency gate.

6. **Hidden chain-of-thought**: `context_manifest` stores only metadata (system prompt references, evidence versions/counts). No raw chain-of-thought content is persisted — verified by column absence and test coverage.

7. **RLS**: All four new tables (`conversations`, `messages`, `model_runs`, `model_run_retrieval_traces`) have RLS enabled following the pattern from migrations 002, 003, and 005b. The join table `model_run_retrieval_traces` resolves workspace via an `EXISTS` subquery on `model_runs`.

8. **Cross-task FKs**: Only tables needed by P3-T04 were created. `citations` (P3-T06) and `feedback` (P3-T08) are deferred to their respective tasks.

9. **`bigint` parsing**: PostgreSQL `bigint` columns (`cost_microunits`) are returned as strings by the `pg` driver. The `toModelRunRow` mapper converts these to `number` (with null handling).

10. **Test parallelism**: `vitest.config.ts` sets `fileParallelism: false` because both `migration.test.ts` and `conversation-repository.test.ts` call `setupTestDatabase()` which drops/recreates the same test database.

## Acceptance-criterion evidence

### 1. Conversations are workspace/project-scoped

- `getConversation` with wrong workspace returns `null` (test: "returns null for cross-workspace access")
- `listConversations` filters by workspace, cross-workspace conversations excluded (test: "lists conversations scoped to workspace")
- `listConversations` supports project filtering (test: "lists conversations filtered by project")
- `deleteConversation` from wrong workspace returns `null` (test: "delete from wrong workspace returns null")

### 2. Messages are immutable after creation

- Repository exports only `createMessage()`, `getConversationMessages()`, `getMessage()` — no update/delete functions exist
- `messages` table has no `status`, `updated_at`, or `deleted_at` column
- Table comment: "Append-only; no UPDATE or DELETE paths are exposed"
- Tests cover create and retrieve only; no test attempts to modify

### 3. Run states cover streaming, completed, cancelled, failed, and interrupted

- `model_run_status` enum: `CREATED`, `STREAMING`, `COMPLETED`, `CANCELLED`, `FAILED`, `INTERRUPTED`
- State machine tests cover all valid CREATED→STREAMING→{terminal} transitions
- Terminal states (COMPLETED, CANCELLED, FAILED, INTERRUPTED) are all tested with `completeModelRun`
- `isTerminalModelRunStatus` correctly identifies non-transitionable states

### 4. Hidden chain-of-thought is not persisted

- `model_runs` table has `context_manifest` (metadata only) — no `chain_of_thought` or `raw_output` column
- Migration column comment: "do NOT store hidden chain-of-thought content"
- Test verifies `context_manifest` contains only metadata, explicitly checks no CoT keys

### 5. Concurrent terminal transitions are controlled

- `completeModelRun` uses `WHERE status = 'STREAMING'` for optimistic concurrency
- Test creates a run, starts streaming, completes it, then verifies second completion throws `ModelRunTransitionError`
- `ModelRunTransitionError` carries both `currentStatus` and `requestedStatus` for diagnostics

### Security: Cross-workspace conversation/message access is denied

- `getConversation` cross-workspace → null
- `getConversationMessages` cross-workspace → empty array
- `getMessage` cross-workspace → null
- `getModelRun` cross-workspace → null
- `deleteConversation` cross-workspace → null (no deletion, returns null)
- RLS enabled on all four tables (verified in tests)

## Security/privacy impact

- **Sensitivity classification**: Conversations carry `sensitivity_class` controlling provider eligibility, logging, retention, and export per `docs/03_DATA_MODEL.md#9`. Default is `INTERNAL`.
- **Workspace isolation**: All repository functions require `workspaceId` as a parameter. Queries include `workspace_id` in WHERE clauses. RLS provides defense-in-depth.
- **No CoT persistence**: Hidden chain-of-thought content is never stored — only metadata in `context_manifest`. This prevents accidental exposure of raw model reasoning.
- **Immutable messages**: Messages cannot be altered after creation, preserving conversation provenance and audit integrity.
- **Optimistic concurrency**: Terminal state transitions are atomic — no race condition can produce duplicated completions.
- **No secrets introduced**: No API keys, credentials, or sensitive values are stored. Provider configuration uses names/versions, not keys.

## Database/API compatibility impact

- **Migration**: New migration `007_conversations_schema.sql` is additive. No destructive changes. Can be rolled back by dropping the new tables and enums.
- **Schema compatibility**: Forward-compatible with citations (P3-T06) and feedback (P3-T08) — those tables reference PKs created here.
- **API compatibility**: New exports from `@pia/db` are additive. Existing exports unchanged. No breaking changes.
- **Type compatibility**: `PersistedMessage` intentionally named to avoid collision with existing `Message` from `@pia/ai`.
