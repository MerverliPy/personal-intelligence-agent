## Design Decisions and Assumptions

1. **Zero external dependencies**: The config package uses only Node.js built-ins (`process.env`) — no `dotenv`, `zod`, or other libraries.
2. **Redacted wrapper class**: Secret values are wrapped in a `Redacted` instance that serializes as `[REDACTED]` via `toString()`, `toJSON()`, and `JSON.stringify`. This prevents accidental logging at the language level.
3. **Schema-based validation**: All config fields are declared in `CONFIG_SCHEMA` with env var name, description, secret flag, required flag, and optional default. This makes the schema self-documenting and testable.
4. **Mode-aware defaults**: In `production` mode, all required fields must be explicitly set. In `development`/`test`, safe defaults are used (e.g., `localhost:9000` for storage, `info` for log level).
5. **Safe error messages**: `ConfigValidationError` includes missing key names and descriptions but never values. The `missingKeys` array enables programmatic handling.
6. **ESM modules**: Config, api, and worker packages use `"type": "module"` for `verbatimModuleSyntax` compatibility with `moduleResolution: "NodeNext"`.
7. **App entry wiring**: API and Worker apps call `loadConfig()` as their first operation and exit with code 1 on failure. Web app (Next.js shell) defers config wiring to P1-T07.
8. **Test strategy**: 14 tests cover development mode, test mode, production mode, missing config errors, error message safety, secret redaction in serialization, safe logging, and invalid NODE_ENV.

   - `apps/api/src/index.ts` and `apps/worker/src/index.ts` call `loadConfig()` as their first operation and `process.exit(1)` on failure.

3. **Test and local defaults cannot be used silently in production mode.**
   - `loadConfig()` rejects production mode when required secrets are missing.
   - In development/test mode, safe defaults are applied.
   - Tested: production mode with missing config throws; development mode with missing optional fields uses defaults.

### Security Checks

- **Secrets are represented only by names/references in examples**: `.env.example` comments out all secret keys (`# OIDC_CLIENT_SECRET=<your-oidc-client-secret>`) and uses only placeholder descriptions.
- **Configuration logging is redacted**: `safeConfigForLogging()` replaces all `Redacted` values with `'[REDACTED]'`. `Redacted.toString()` and `Redacted.toJSON()` always return `'[REDACTED]'`. Tested by `safeConfigForLogging > redacts all secret values`.
