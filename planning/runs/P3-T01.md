## Design decisions and assumptions

1. **Fake adapter location**: Inside `packages/ai/src/gateway/` — mirrors the embedding pattern (`fake-provider.ts` in knowledge package).
2. **Config schema**: Added `model.*` block (6 fields) mirroring `embedding.*` pattern exactly.
3. **OpenAI API surface**: Used Chat Completions API (stable, universal) rather than Responses API. The `ModelGateway` interface abstracts this entirely — switching to Responses API later is a provider-internal change.
4. **Sensitivity policy**: Minimal `SensitivityPolicy` interface with permissive default (allows all except PROHIBITED). Extensible by later phases (P4, P5).
5. **Error taxonomy**: `ModelGatewayError` class with 9 stable `ErrorCategory` values. OpenAI errors mapped through `instanceof` checks and HTTP status codes.
6. **Observability**: No direct integration in this task — `ModelGatewayConfig` and `model` result field provide provider/model provenance for downstream metrics.
7. **Streaming contract**: `GenerationEvent` union type with `text_delta`, `tool_call_*`, `error`, `done` — normalized across providers.

## Acceptance-criterion evidence

| Criterion                                                             | Evidence                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider SDK objects do not cross the adapter boundary                | `ModelGateway` interface uses only `GenerationRequest`/`GenerationResult`/`GenerationEvent`. OpenAI types never exported from `index.ts`. Adapter imports `openai` internally only.                                                                         |
| Streaming cancellation and timeout are tested                         | `gateway.test.ts` tests AbortSignal with `generate()` and `stream()`. `openai-adapter.ts` passes AbortSignal to SDK and checks `signal?.aborted` in stream loop. Timeout config flows through `MODEL_TIMEOUT_MS` → `config.timeoutMs` → SDK timeout option. |
| Usage, latency, provider/model/config, and stable errors are captured | `GenerationResult.usage` captures prompt/completion/total tokens. `GenerationResult.model` captures provider config. `ModelGatewayError.category` maps to 9 stable error categories. Openai adapter maps all SDK error classes + HTTP status codes.         |
| Sensitivity/provider policy can deny routing before a request is sent | `SensitivityPolicy.canRoute()` is checked in `checkPolicy()` before any SDK call. Default policy denies `PROHIBITED`. Tested in `gateway.test.ts`.                                                                                                          |
