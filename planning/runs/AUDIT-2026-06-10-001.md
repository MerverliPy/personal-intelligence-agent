## Design decisions and assumptions

1. **F-003 (Option B — defer):** Server-side revocation removed rather than fixed, as a Redis-backed `RevocationStore` is not yet implemented. Session tokens remain valid until natural expiry (max 24h). Cookies are HttpOnly + SameSite=Lax. Full revocation is deferred per P1-T02 run record.

2. **F-004:** The guard normalizes null, primitives, and arrays to `{}` before hashing. This is safe because the idempotency plugin only invokes `hashPayload` with `request.body ?? {}`, which is always an object for JSON POST bodies. The guard is defense-in-depth.

3. **F-005:** Single pool reused across all health checks. Cleaned up on Fastify server `onClose` hook. No connection leak.

4. **F-006:** Tracked file count (221) sourced from `git ls-files | wc -l` at repair time.
