## Design decisions

1. **Prompt-based markers**: Model emits `[cite:<chunk-id>]`, `[infer]`, `[assume]` markers inline. Builder parses deterministically. No extra embedding calls.
2. **Both provisional + batch**: Streaming parser emits `citation.provisional` during generation; final `response.completed` carries the authoritative `Citation[]` array.
3. **Insufficient evidence via flag**: `response.completed` gains `insufficient_evidence?: boolean`. When retrieval returns zero evidence, generation is skipped and a canned message is returned with `insufficient_evidence: true`.
4. **PENDING verification**: P3-T06 inserts `verification_status = 'PENDING'`. P3-T07 owns the verification state machine.
5. **Evidence chunk IDs in compiled context**: Evidence blocks include `<evidence_chunk id="chk-uuid">text</evidence_chunk>` so the model knows which UUIDs to cite.
6. **Cleaned text stored in messages**: Assistant message `content` stores the stripped text (markers removed). Raw model output with markers is used only by the citation builder.

## Acceptance-criterion evidence

1. **Every citation references a chunk present in the run evidence set.**
   - `buildCitations()` at `packages/knowledge/src/citations/builder.ts:89` validates every `chunkId` against the `evidenceMap`. Invalid chunk IDs are silently dropped (test: "drops citations for chunk IDs not in the evidence set").

2. **Citation stores document version and locator.**
   - `CreateCitationInput` includes `documentVersionId` and `sourceLocator`. The `citations` table has `document_version_id uuid NOT NULL` and `source_locator jsonb NOT NULL`. Tests verify both are populated.

3. **No-result requests produce an insufficient-evidence response rather than invented citations.**
   - `orchestrator.ts:238–263`: When `evidence.length === 0`, skips generation, returns `insufficient_evidence: true` with `citations: []`.

4. **Source preview is authorized and location-specific.**
   - `sourceLocator` stores the structural locator (page, line, section) from the original `RetrievalResult.locator`. Workspace-scoped RLS on `citations` table prevents cross-workspace access.

## Security/privacy impact

- **RLS on citations table**: `citations_rls` policy ensures workspace isolation via `app.current_workspace_id`.
- **No hidden chain-of-thought**: Raw model output with markers is temporarily held in memory during generation but only cleaned text is persisted.
- **Citation preview**: Clients receive `chunk_id`, `document_version_id`, and `source_locator` — must be authorized to view the referenced source via document-level access.
- **No new secrets or credentials** introduced.

## Database/API compatibility impact
