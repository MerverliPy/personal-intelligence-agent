## Design decisions and assumptions

1. **PostgreSQL image**: `pgvector/pgvector:pg17` — official pgvector image with PostgreSQL 17, provides vector extension out of the box.
2. **Redis image**: `redis:7-alpine` — lightweight, sufficient for development.
3. **MinIO image**: `minio/minio:latest` — S3-compatible object storage for local development.
4. **Credentials**: All defaults (`pia`/`pia-dev`, `minioadmin`/`minioadmin`) are development-only and clearly marked as such.
5. **Network binding**: All ports bound to `127.0.0.1` only, preventing network exposure.
6. **Health checks**: Each service has an independent health check using the service's native CLI (`pg_isready`, `redis-cli ping`, `curl /minio/health/live`).
7. **Volume persistence**: Named volumes preserve data across `docker compose down`; only explicit `--volumes` flag or `teardown-deps.sh` removes them.
8. **Bucket initialization**: The `start-deps.sh` script uses MinIO Client (`mc`) from inside the container to create the `pia-local` bucket idempotently after services are healthy. This avoids complex init-container patterns in compose.
9. **Service naming**: All containers and volumes prefixed with `pia-` for clear identification.
10. **Compose project name**: Set to `pia-dev` explicitly in `compose.yaml` via `name:` field.
