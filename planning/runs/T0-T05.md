## Design decisions and assumptions

1. **Dependency inversion**: `Tracer` and `Meter` are no-op by default. Domain code depends on interfaces, not implementations. Switching to OpenTelemetry in the future requires only registering a new adapter — no domain code changes.
2. **AsyncLocalStorage for correlation**: Matches Node.js best practices for context propagation across async call chains. No framework dependency.
3. **Sensitive field redaction at logger boundary**: The logger automatically calls `redactSensitiveFields()` on every meta object before output. Applications never need to remember to redact.
4. **Case-insensitive field matching**: `SENSITIVE_LOG_FIELDS` entries are stored lowercase; lookups use `.toLowerCase()`. This catches `Authorization`, `AUTHORIZATION`, `AccessToken`, `access_token`, etc.
5. **`[REDACTED]` marker**: Uses the same marker convention as `@pia/config`'s `Redacted` class for consistency.
6. **Child logger bindings at root level**: Unlike per-call `meta` (which goes under `data`), child logger bindings like `component` or `route` are merged into the log entry root for structural querying.

## Acceptance-criterion evidence

### 1. Every API request and worker job has a correlation identifier

- `apps/api/src/index.ts` wraps startup in `runWithCorrelation()`, which creates a fresh UUID.
- `apps/worker/src/index.ts` wraps startup in `runWithCorrelation()`, which creates a fresh UUID.
- The logger automatically extracts the correlation ID from context and injects it into every log entry.
- Tests prove: `createCorrelationContext()` generates unique UUIDs; `runWithCorrelation()` propagates context through synchronous call chains; `getCurrentCorrelationId()` returns `undefined` outside context.

### 2. Structured logs exclude configured sensitive fields

- `SENSITIVE_LOG_FIELDS` combines hardcoded patterns (authorization, cookie, token, password, secret, key, etc.) with `SECRET_FIELD_NAMES` from `@pia/config`.
- `redactSensitiveFields()` deeply redacts matching fields in objects and arrays.
- The logger calls `redactSensitiveFields()` on every meta payload before output.
- Tests prove: authorization headers become `[REDACTED]`; tokens/passwords/secrets are redacted; `DATABASE_URL` etc. from config are redacted; original secrets never appear in output.

### 3. Telemetry can be disabled or exported without changing domain code

- `createObservability({ enabled: false })` creates a logger at `error` level with no-op tracer/meter.
- Domain code calls `logger.info(...)` or `tracer.startSpan(...)` regardless of enabled/disabled state — no `if (enabled)` branching required.
- Tests prove: disabled context returns functional interfaces that accept calls without throwing.

## Security/privacy impact

- **Secrets never appear in log output**: 11 distinct sensitive field categories are redacted (authorization, tokens, credentials, cookies, sessions, signatures, keys, passwords, config secrets).
- **Redaction is case-insensitive and deep**: Covers camelCase, snake_case, and UPPERCASE variants; handles nested objects and arrays.
- **Correlation IDs are non-identifying**: UUID-based, no PII embedded.
- **No secrets in source code**: The only "secret-ish" strings are field name patterns in `redact.ts`, never actual credentials.
- **`no-console` warnings are intentional**: The logger is the sole transport; eslint exceptions are explicit with justification comments.

## Remaining risks or follow-up tasks

- **OpenTelemetry integration**: The `Tracer`/`Meter` interfaces are ready for an OTel adapter (future task). Currently all spans/metrics are no-ops.
- **Rich trace propagation for HTTP middleware**: When Fastify is introduced (P1-T07), middleware should set up correlation context per request (header extraction, propagation). The `CorrelationContext` already supports `traceId`/`spanId` fields for this purpose.
- **`no-console` lint warnings in app shells**: The `console.error` calls in the catch blocks are the last-resort fallback before exit. Acceptable as-is; will be replaced when full error handling is implemented.
