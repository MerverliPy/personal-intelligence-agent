## Design Decisions and Assumptions

- **Scope is "what unblocks CI", not "every prettier diff".** The working tree also has uncommitted changes to `AGENT_HANDOFF.md`. Those are audit-handoff content edits, not a CI-blocking format issue, so they are explicitly out of scope for this commit. Bundling them with a CI fix would mix concerns and force the audit-handoff reviewer to re-approve a CI-fix commit.
- **New commit, not amend.** AUD-P3-102's commit message already records run-record evidence for the orchestrator and provider-failure changes. Amending would either (a) invalidate that evidence pointer or (b) require re-running every command listed there. A separate `chore(format)` commit keeps the audit fix intact and the new commit's run record self-contained.
- **No new `git push` from this agent.** `AGENTS.md` prohibits pushing. The user pushes the branch and re-runs CI.
- **Preventive follow-up is a planning task, not a code change in this commit.** A pre-push hook that gates PR-branch pushes (not just `main`) and a run-record template line requiring `pnpm format:check` evidence belong in a backlog task so the prevention is reviewable on its own.
