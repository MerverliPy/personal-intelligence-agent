## Findings and Decisions

1. **Path-boundary interpretation accepted.** The P2-T09 precedent (commit `53af795`) established that `apps/api/src/routes/web*.ts` is the canonical serving layer for the `@pia/web` package. P3-T09 follows the same pattern with a new `web-conversations.ts` route and a one-line `server.ts` registration.
2. **Run-state visual distinction.** `CANCELLED` and `INTERRUPTED` originally shared the `badge-quarantined` CSS class. Split them into `badge-cancelled` and `badge-interrupted` to satisfy AC#3 ("visibly distinct") and the test for unique classes per state. Added the new CSS classes to `shared.ts`.
3. **SSE parser CRLF handling.** The initial parser split on `\n\n`, which left `\r` characters on CRLF line endings. Fixed by accepting `\r?\n\r?\n` as the event-boundary separator. This is compliant with the SSE spec which allows `\n`, `\r`, or `\r\n` as line endings.
4. **Client-side SSE parser is inlined** in `conversation-detail.ts` because the page is rendered as a single ES module without bundling. The server-side parser in `conversation-shared.ts` is the authoritative implementation and is unit-tested; the client-side parser mirrors it.
5. **Citation modal renders synchronously** from the in-memory citation object. A `NO-FETCH GUARANTEE` test stubs `globalThis.fetch` and asserts it is never called from `renderCitationModalBody`.
6. **Feedback form is a sibling of the message** (not nested inside). The `feedback-form.test.ts` includes a structural test that asserts the form appears AFTER the `.message-content` div in the rendered HTML and is not nested inside it.
7. **Static a11y coverage** is unit-level only. The `a11y-static.test.ts` suite asserts: every interactive element has accessible text or `aria-label`; no positive `tabindex`; forms have explicit `<label>` associations; landmarks are present; the citation modal uses a native `<dialog>` element. Browser-based axe-core/Playwright tests are deferred to a follow-up.

## Acceptance-Criterion Evidence

### AC#1: User can create a conversation and receive a streamed response

- `apps/web/src/pages/conversation-list.ts` renders the "New conversation" form and handles POST to `GET /v1/workspaces/{wid}/conversations` then redirects to the detail page.
- `apps/web/src/pages/conversation-detail.ts` renders the message thread and opens an SSE stream via `fetch` + `ReadableStream` when the user sends a message.
- The stream is consumed by an inline SSE parser that dispatches `run.started`, `response.delta`, `citation.provisional`, `response.completed`, `run.failed`, and `approval.required` events.
- The `sse-client.test.ts` (12 tests) proves the parser handles all 6 event types and edge cases (chunked buffers, CRLF, comments, keepalives).
- API endpoints: `POST /v1/workspaces/{wid}/conversations` (create), `POST /v1/workspaces/{wid}/conversations/{cid}/messages` (send, returns 202 + run), `GET /v1/workspaces/{wid}/conversations/{cid}/events?run_id={rid}` (SSE).

### AC#2: Citations open an authorized source/version/locator preview

- `renderCitationChip` renders a real `<button>` with `aria-haspopup="dialog"`, `data-citation-id`, and a truncated `aria-label` containing the claim text.
- `renderCitationModalBody` renders source/version/locator/verification_status and the claim text. Every field is HTML-escaped at render time.
- The modal is opened by the `<dialog>` element (native focus management; Escape closes natively).
- The `citation-modal.test.ts` (11 tests) proves: XSS guards for script tags, ampersands, quotes; locator formatting (page, ordinal, JSON fallback); **NO-FETCH GUARANTEE** (the modal renders synchronously from the in-memory citation, never calling `fetch`).
- P3-T07 already enforces workspace scoping on citation verification.

### AC#3: Cancelled/failed runs are visibly distinct from completed answers

- `renderRunStateBadge` maps each of the 6 run states (`CREATED`, `STREAMING`, `COMPLETED`, `CANCELLED`, `FAILED`, `INTERRUPTED`) to a unique CSS class, a human-readable label, and a descriptive ARIA label.
- CSS classes: `badge-pending`, `badge-processing`, `badge-ready`, `badge-cancelled`, `badge-failed`, `badge-interrupted`. All 6 are visually distinct (different background + text colors).
- The `run-state-badge.test.ts` (5 tests) proves: every state uses `role="status"`, every state has a unique CSS class, every state has a unique visible label, ARIA labels are descriptive, and content is HTML-escaped.

### AC#4: Feedback can be submitted without altering the original message

- `renderFeedbackForm` renders a `<form>` that is a sibling of the message content (not nested inside).
- The `feedback-form.test.ts` includes a structural test that asserts the form appears AFTER the `.message-content` div in the rendered HTML and is not nested inside it.
- The submit handler calls `POST /v1/workspaces/{wid}/messages/{mid}/feedback` (P3-T08 endpoint) and never mutates the original message DOM.
- The form includes all 8 feedback categories (`FEEDBACK_CATEGORIES` frozen list, matching P3-T08's enum).
- Correction and notes textareas have a `maxlength` attribute matching the API's `FEEDBACK_TEXT_MAX_BYTES` default (4096 bytes). The server is the authoritative length cap; this is a UX hint.

### AC#5: Core workflow is keyboard accessible (NFR-UX-001, NFR-UX-003)

  - Every `<button>` has accessible text or `aria-label`.
  - Every `<input>`, `<select>`, `<textarea>` has an associated `<label>`.
  - No positive `tabindex` (natural tab order).
  - The message thread uses `role="log"` with `aria-live="polite"` for screen reader announcements.
  - The citation modal uses a native `<dialog>` element (browser handles focus trap and Escape-to-close).
  - The "Conversations" tab is added to the tab bar with proper `role="navigation"`.

## Security and Privacy Impact

- **Workspace scoping.** Every page load validates the `workspace_id` URL param against the session (via the existing `requireWorkspaceContext` plugin). The page builders are pure functions of the URL params; no client-side state is shared across workspaces.
- **Untrusted content rendering.** Every user-supplied field (message content, citation `claim_text`, correction, notes, source_locator values) passes through `escapeHtml` at render time. The `citation-modal.test.ts` and `feedback-form.test.ts` include explicit XSS-guard tests.
- **CSRF.** The feedback POST is a state-changing write; the existing `csrfPlugin` in `apps/api/src/plugins/security.ts` covers it. The feedback form is served same-origin, so the session cookie is automatically attached.
- **Open redirect / path traversal.** Conversation list/detail URLs are constructed from server-rendered workspace IDs, not user input.
- **Information disclosure.** Error messages from the SSE stream are rendered as user-safe copy. The `run.failed` event's `error.message` is passed through the `showError` helper which uses `escapeHtml`.
- **No-fetch guarantee for citation modal.** The modal renders from the in-memory citation object; it does not fetch additional resources that could bypass the workspace context.
- **Audit logging.** The feedback form submission is handled by the existing P3-T08 audit logging in `apps/api/src/routes/feedback.ts:181-200` (audit event with category, hasCorrection, hasFailureClass, hasSuggestion, traceCount).
