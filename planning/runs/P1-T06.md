## Design Decisions and Assumptions

1. **Transactional outbox via PoolClient**: `publishOutboxEvents` accepts a raw `PoolClient` from `pg` so the caller manages the transaction. This ensures atomicity — domain writes and outbox events share the same transaction. The caller (API layer) is responsible for BEGIN/COMMIT/ROLLBACK.

2. **Outbox schema from P1-T01**: Leverages the existing `outbox_events` table. No new migrations are needed.

3. **Consumer uses SELECT ... FOR UPDATE SKIP LOCKED**: Prevents duplicate processing across concurrent workers. The fetch atomically acquires rows and marks them as PROCESSING.

4. **Handler idempotency is the handler's responsibility**: The consumer ensures at-most-once delivery semantics via PROCESSING status gating, but handlers must tolerate at-least-once delivery in crash scenarios. "Duplicate delivery does not duplicate handler effects" is achieved by:
   - Consumer marks status PROCESSING before invoking handler → competing consumers skip the job
   - Handlers must implement their own idempotency (e.g., check COMPLETED state, use idempotency keys)

5. **Retry/Dead-letter**: Exponential backoff with jitter (±25%) for retryable errors. `TerminalJobError` skips retries and moves directly to DEAD. After max attempts (default 5), exhausted jobs also go to DEAD.

6. **Worker identity**: `JobContext.workerIdentity` is explicit, satisfying the security check requirement.

7. **No database dependency in tests**: The jobs package depends on `@pia/db` only as a devDependency for test helpers. Production code depends only on `pg` and `@pia/observability`.

## Security/Privacy Impact

- **No new secrets** introduced.
- **Worker identity** is explicit and logged per job invocation.
- **No payload inspection** is performed by the outbox or consumer — sensitive content redaction is the responsibility of the handler and the logger.
- **Job payloads are stored in `outbox_events.payload` (jsonb)** — these persist even after completion. This is by design for auditability. Future phases should ensure handlers strip sensitive content from payloads.

## Database/API Compatibility Impact

- **No schema changes** — the `outbox_events` table from P1-T01 is unchanged.
- **JobConsumer** adds a new polling pattern to the worker app. It does not conflict with any existing consumer.
- **No API contract changes** — API endpoints are unchanged.
