## Design Decisions and Assumptions

### Parser Interface

- **Parser** abstraction: `id`, `version`, `supportedMimeTypes`, `supportedExtensions`, `parse()`, `canParse()`.
- `findParser()` registry selects the first matching parser by MIME type with extension fallback.
- `ParserError` with `reasonCode` for stable error classification.

### Parser Implementations

- **PlainTextParser**: Handles text/plain, text/markdown, text/csv, text/html, application/json, text/xml. Detects format variant (markdown vs csv vs plain) and applies appropriate normalization. Markdown headings produce `heading` locators with level. CSV produces `line` locators per row.
- **PdfParser**: Wraps `pdf-parse` (pure JS, no network access). Extracts text with page boundaries. Each page gets a `page` locator; paragraphs within pages get `paragraph` locators. Falls back to single-page locator if pdf-parse doesn't emit form-feeds.
- **DocxParser**: Wraps `mammoth` (pure JS, no network access). Converts DOCX to raw text, then heuristically detects headings vs paragraphs by line characteristics.

### Extraction Stage

- `createExtractionStage(options)` replaces `noopExtractionStage`. Takes a `pool`, optional parser list, optional limits, and optional `loadFileContent` adapter.
- Loads stored file metadata via `getStoredFileById`, then calls `loadFileContent` to get the binary buffer.
- Selects parser via `findParser`, parses with timeout, stores results in `extraction_metadata` JSONB (pipeline version, parser ID, character count, locator summaries, full locator array, text preview).
- Is idempotent: `isComplete()` checks for `parserId` and matching `pipeline` key in metadata.
- Throws `TerminalJobError` for unsupported formats, missing content loader, extraction timeout, and parser errors.

### Security

- All parsers use pure-JS libraries (`pdf-parse`, `mammoth`) — zero network access.
- Parsing respects configured size limits and timeouts.
- Malformed/encrypted inputs throw `ParserError` (terminal), not cryptic exceptions.
- Fixture tests verify malformed input rejection for PDF and DOCX.

### Normalized Document Model

- `ParsedDocument`: `text` (full normalized content), `locators` (structural spans), `metadata` (format, parser, timing, counts).
- All locator offsets are zero-based character indices into `text`.
- Locator types: `page`, `section`, `heading`, `paragraph`, `table`, `list`, `list_item`, `line`.

## Security/Privacy Impact

- **Positive**: All three parsers are pure-JS libraries with zero network access. No content leaves the process.
- **Positive**: Malformed and malicious inputs are caught and reported as terminal errors, preventing infinite processing.
- **Positive**: The extraction stage stores only structured metadata and text previews (first 500 chars) in `extraction_metadata` JSONB. Full text will be stored in chunks (P2-T05).
- **Neutral**: `pdf-parse` and `mammoth` have known CVE histories (resolved in locked versions). Dependency scan shows no active issues.

## Database/API Compatibility Impact

- **No schema changes**: Extraction results stored in existing `document_versions.extraction_metadata` JSONB column.
- **API impact**: `createExtractionStage` is a drop-in replacement for `noopExtractionStage` — same `IngestionStage` contract, same stage name (`"extraction"`).
- **Breaking**: `createExtractionStage` requires a `loadFileContent` adapter to read binary file content. Callers must wire this adapter when using the real extraction stage instead of the noop.

## Remaining Risks or Follow-up Tasks

- **PDF page detection**: pdf-parse may not emit form-feed characters for all PDFs. The parser falls back to a single `page` locator when no page breaks are detected. Accurate page boundaries depend on pdf-parse output quality.
- **DOCX heading detection**: Mammoth raw text extraction does not preserve heading levels. Heuristic detection (short lines followed by blank lines) is imperfect and may misclassify some paragraphs as headings.
- **No XLSX/PPTX support**: Only DOCX is supported for Office formats. XLSX is listed in the allowed MIME types but has no parser yet.
- **Text preview truncation**: Only first 500 characters of parsed text are stored in `extraction_metadata`. The chunking stage (P2-T05) will need the full text, which should be stored separately or retrieved from extraction metadata with the full locator array.
