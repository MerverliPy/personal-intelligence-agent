## Design Decisions

### 1. Cursor-based pagination for document listing

Documents use cursor-based pagination on `created_at DESC`, matching the established workspace/project pattern. Offset-based `listDocuments()` from the knowledge package is bypassed in favor of raw SQL with cursor support.

### 2. Status filtering via JOIN on document_versions

The `status` query parameter joins `document_versions` to filter documents by version status. This avoids the complexity of subqueries while preserving the ability to find documents with versions in a particular state (e.g., "READY").

### 3. Ingestion job idempotency

Uses the `Idempotency-Key` header processed by the existing idempotency plugin, combined with a `UNIQUE(workspace_id, idempotency_key)` constraint on `ingestion_jobs`. On duplicate key, falls back to returning the most recent existing job for that version.

### 4. Retrieval trace role gating

Debug trace inspection (`GET .../retrieval/traces/{tid}`) requires ADMIN, OWNER, or AUDITOR role. Gate is checked against the `workspace_members` table on every request. This prevents members and curators from inspecting internal retrieval state.

### 5. Type mapping at API boundary

Internal knowledge package types (camelCase, `readonly` properties) are transformed to API contract types (snake_case, OpenAPI shapes) at the route layer. This keeps the contracts package stable and independent of internal implementation details.

### 6. Fake embedding provider for development

The retrieval service uses `fakeEmbeddingProvider` with `defaultFakeModelConfig()`. This provides deterministic vector search without requiring a real embedding API key. Production deployment will swap this for a real provider configured via `@pia/config`.

## Security/Privacy Impact

- **No new secrets**: No credentials, API keys, or tokens introduced.
- **Workspace isolation**: Every SQL query includes mandatory `workspace_id` filter. Route handlers verify membership before querying.
- **Role-gated trace access**: Retrieval trace inspection restricted to elevated roles, preventing information disclosure of retrieval internals.
- **Error safety**: 404 responses do not distinguish between "not found" and "no permission" — both return `FORBIDDEN` or `NOT_FOUND` with identical shapes. No resource metadata leaks in errors.
- **Idempotency**: Ingestion job creation is idempotent to prevent duplicate jobs from retried requests.
- **Schema validation**: Fastify schema validation rejects malformed input at the framework level before reaching application code.

## Remaining Risks or Follow-up Tasks

1. **Real embedding provider**: `fakeEmbeddingProvider` used for development. Production needs a real provider (OpenAI, etc.) behind the existing `EmbeddingProvider` interface. Requires API key configuration.
2. **DB-dependent integration tests**: Full end-to-end tests of document/retrieval endpoints require a running PostgreSQL instance. Current contract tests accept graceful degradation (500) when DB is absent. See `test:integration` for DB-dependent suites.
3. **Pagination cursor format**: Document listing uses timestamp-based cursors. Consider switching to UUID-based cursors (`created_at, id`) for tie-breaking if documents are created at identical timestamps within a transaction.
4. **Retrieval configuration versioning**: The `configuration_version: '1.0.0'` is hardcoded. Should be sourced from the retrieval config persisted in the database.
5. **P2-T09 dependency**: This task exposes the retrieval and document APIs; P2-T09 (Build document and retrieval UI) depends on these endpoints being available.
