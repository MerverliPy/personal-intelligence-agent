### Security: Feedback text is untrusted and access-controlled (security_checks)

- **Workspace isolation.** All repository functions require `workspaceId`; RLS policies on `feedback` and `feedback_retrieval_traces` enforce defense-in-depth. Tests verify cross-workspace read returns `null` / empty array.

- **Schema validation.** `additionalProperties: false` on the POST body rejects unknown fields.
- **HTML escaping.** Free-text is stored verbatim. The route contract documents that the render layer (P3-T09) is responsible for HTML escaping. A future task can add an `escapeForDisplay` helper in the AI module if needed.
- **Classifier safety.** `classify()` is a pure function of `category`; the free-text argument is ignored by design. The `SECURITY` block in `feedback-classifier.test.ts` asserts that:

  - Script tags and HTML are ignored.
  - Role-override attempts are ignored.
  - Different-length free-text produces the same suggestion.
- **Audit.** POST emits a `feedback.create` audit event with category, messageId, hasCorrection, hasFailureClass, hasSuggestion, and traceCount.

## Follow-up: Integration Test Fixture Fixes

The independent review (see `planning/reviews/P3-T08.md`) returned `PASS_WITH_FOLLOW_UP` and identified 4 broken integration tests in `packages/db/test/feedback-retrieval-traces-repository.test.ts`. Both reviewers (`reviewer` and `security`) had already returned PASS; the follow-up was test-fixture defects only, not implementation defects.

### Root causes

- **Root cause A (3 tests):** The `insertTrace` helper inserted a `retrieval_configs` row with hard-coded `name='fb-trace-config', version='1.0.0'`. The schema enforces `UNIQUE (workspace_id, name, version)` (migration 005, line 25), so the second call within the same workspace violated the unique constraint. Affected tests: `inserts trace links and returns the count`, `removes all links for a feedback row`, `returns retrieval trace IDs linked to the feedback`.
- **Root cause B (1 test):** The cap test passed 65 copies of the same zero UUID. The implementation's `Array.from(new Set(retrievalTraceIds))` dedupes input *before* the cap check, collapsing 65 identical UUIDs to 1, so the rejection path was never exercised.

### Fixes applied

- **Fix A:** `insertTrace` now derives a unique `name` from `Date.now()` + a random suffix on every call.
- **Fix B:** The cap test now generates 65 distinct UUIDs via `Array.from({ length: MAX_FEEDBACK_RETRIEVAL_TRACES + 1 }, () => randomUUID())`, and imports `randomUUID` from `node:crypto`.

## Risks and Assumptions

- **PG 12+ assumption.** `ALTER TYPE ADD VALUE IF NOT EXISTS` requires PostgreSQL 12+ when used inside a transaction block. The development stack uses `pgvector/pgvector:pg17` per `compose.yaml:8`; CI and production environments are expected to use PG 12+. The migration header documents this requirement.
- **Migration runner transaction behavior.** The migration runner at `packages/db/src/migrate.ts:47-60` wraps each migration in a `BEGIN`/`COMMIT` transaction. PG 12+ supports `ALTER TYPE ADD VALUE` inside transactions, so this is safe on the target version.
- **Retrieval-trace provenance.** The `feedback_retrieval_traces` table does not FK to `model_run_retrieval_traces`. Application-layer validation (trace must belong to a model_run linked to the same message) is the authoritative check. A future task can add a DB-level constraint or trigger if the application-layer check is deemed insufficient.
- **HTML escaping is deferred to the render layer.** Storing plain text preserves the user's original input. The render layer (P3-T09) must escape at display time. This is documented in the route header comment.
- **Cross-workspace isolation in tests.** The `feedback-repository.test.ts` and `feedback-retrieval-traces-repository.test.ts` tests use `setupTestDatabase()` which drops and recreates `pia_test`. This is an isolated disposable test database; no persistent or shared data is affected.
