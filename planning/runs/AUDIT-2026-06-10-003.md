## Missing Capability Reproduced

All five findings were confirmed present in the codebase:

1. **S-H1**: CSRF cookie on line 90 of `security.ts` set without `; Secure` — cookies could be transmitted over unencrypted HTTP.
2. **S-H2**: `getStoredFileByKey` query (`SELECT * FROM stored_files WHERE storage_provider = $1 AND object_key = $2`) had no `workspace_id` filter — cross-tenant data leak possible.
3. **S-H3**: `securityHeadersHook` in `security.ts` did not set `Strict-Transport-Security` header — no HSTS protection.
4. **S-M1**: CSP `default-src 'none'` blocked the web shell's inline `<script type="module">` and `fetch()` calls.
5. **S-M6**: `DEFAULT_POOL_CONFIG` in `client.ts` had hardcoded credentials (`postgresql://pia:pia-dev@localhost:5432/pia`).

## Design Decisions and Assumptions

### S-H1 & S-H3 — Production-gating

Both the CSRF `Secure` flag and `Strict-Transport-Security` header are enabled only when `process.env['NODE_ENV'] === 'production'`. This is because:

- `Secure` cookies won't work over plain HTTP in development
- HSTS over `localhost` breaks local development workflows
- The check is consistent with `server.ts` line 61: `trustProxy: mode === 'production'`

### S-H2 — Workspace scoping

Added `workspaceId` as the **first** parameter to `getStoredFileByKey` to match the convention used by other repository functions (e.g., `getStoredFileById(pool, workspaceId, id)`). The primary key `(storage_provider, object_key)` is unique per stored file but not tenant-scoped — adding `workspace_id` prevents cross-tenant object-key enumeration.

### S-M1 — CSP relaxation

The CSP was relaxed from:

```
default-src 'none'; frame-ancestors 'none'; form-action 'self'
```

to:

```
default-src 'none'; script-src 'self' 'unsafe-inline'; connect-src 'self'; frame-ancestors 'none'; form-action 'self'
```

This allows the web shell (`/app`) to execute its inline module script and call API endpoints. The `'unsafe-inline'` is accepted because the entire `<script>` is server-rendered, not user-supplied. In a future iteration, the script could be extracted to a separate file and served with a nonce.

### S-M6 — Credential removal

Changed the fallback from `postgresql://pia:pia-dev@localhost:5432/pia` to `postgresql://localhost:5432/pia`. Development credentials are already in `.env.example`, so developers copy that. Production always sets `DATABASE_URL` explicitly via the config system.
