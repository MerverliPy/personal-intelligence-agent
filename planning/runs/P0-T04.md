## Design decisions and assumptions

1. **Single job with sequential steps**: Uses one GitHub Actions job with sequential steps rather than separate jobs. This ensures:
   - Each stage is independently visible in the GitHub UI.
   - Failures stop the pipeline immediately at the failing stage.
   - No `continue-on-error` anywhere — failures are never masked.
   - Simpler YAML, no inter-job artifact passing needed at this stage.

2. **Trigger strategy**: Runs on push to `main` and all PRs targeting `main`. This covers both the protected branch and pre-merge validation.

3. **Concurrency**: `cancel-in-progress: true` prevents wasted CI minutes when multiple pushes occur to the same branch/PR.

4. **Node/pnpm version**:
   - pnpm: `pnpm/action-setup@v4` with `version: 9` (matches `.tool-versions` and `packageManager` field).
   - Node: `actions/setup-node@v4` with `node-version-file: .nvmrc` (currently Node 22).
   - pnpm cache: enabled via `cache: pnpm` on `setup-node`.

5. **Timeout**: 15 minutes. Current full suite completes in under 1 minute (all cached); generous headroom for future test growth.

6. **Caching strategy**:
   - `actions/setup-node` caches the pnpm store automatically.
   - `turbo` local cache is not explicitly cached with `actions/cache` — at this stage the Turborepo cache is local-only. Can be added later if build times grow.

7. **Local CI script**: `scripts/ci/check-all.sh` mirrors the CI workflow step-for-step, giving developers a single command (`pnpm ci:check`) to run all gates before pushing.

8. **`.gitignore` additions**: `/ci-output/` and `/test-results/` are reserved for future CI artifact output (e.g., test JUnit XML, coverage reports). Not currently generated, but pre-emptively excluded.

9. **Runner**: `ubuntu-latest` — the standard GitHub-hosted runner. No self-hosted runner needed at this phase.

10. **No Docker services in CI yet**: P0-T03 created `compose.yaml` but the CI workflow does not currently run `docker compose up`. This is intentional — no tests require database/Redis/object-store yet. Service containers will be added when integration tests are introduced in P1.

## Security/privacy impact

- **No secrets introduced.** The CI workflow uses only public GitHub Actions (`actions/checkout@v4`, `pnpm/action-setup@v4`, `actions/setup-node@v4`). No API tokens, credentials, or secrets are hardcoded.
- **No secrets in scripts.** `scripts/ci/check-all.sh` contains no credentials.
- **Cache isolation.** pnpm cache uses GitHub's built-in cache scoped to the repository. No cross-repo cache leakage.
- **.gitignore coverage.** All build outputs, test artifacts, and environment files are excluded from version control.
- **Workspace scoping.** No tenant data or multi-tenant constructs are involved in CI infrastructure.

## Database/API compatibility impact

- **No database changes.** Pure CI infrastructure — no migrations, no schema changes.
- **No API changes.** No contract changes, no endpoint modifications.
- **No deployment changes.** This task only defines the quality gate pipeline; it does not deploy anything.

## Remaining risks or follow-up tasks

- **No Docker services in CI**: P0-T03's `compose.yaml` services are not started in CI. P1 tasks will need to add `services:` to the CI workflow or use `docker compose up` steps when integration tests require PostgreSQL/Redis/MinIO.
- **No turbo remote caching**: Remote Turbo cache (e.g., Vercel) is not configured. Local cache reuse works but CI cache is per-run. Can be added later for faster CI.
- **No OpenAPI validation**: `docs/07_TEST_EVALUATION_STRATEGY.md` mentions OpenAPI validation and breaking-change detection. This will be added when API contracts are implemented (P1-T07, P2-T08).
- **No secret/dependency scanning yet**: These are covered by P0-T06 (threat model and security checks).
- **No deployment workflow**: Only CI (quality gates) is defined. CD (deployment) is out of scope for P0.
- **GitHub Actions needs to be enabled**: For the workflow to actually run, GitHub Actions must be enabled on the repository. This is a one-time GitHub UI setting, not code.
