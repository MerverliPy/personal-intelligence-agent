## Design Decisions and Assumptions

1. **Staged framework with extensible stages**: The workflow defines four ordered stages (extraction, chunking, embedding, publishing). Each stage implements the `IngestionStage` interface with `execute()` and `isComplete()`. Stages are pluggable — the worker constructs the handler with noop stages that P2-T04/T05/T06 will replace with real implementations.

2. **Stage checkpoints for resumption**: After each stage completes, `ingestion_jobs.stage` is updated. On re-delivery (worker crash, retry), the workflow reads the checkpoint and skips already-completed stages. The `isComplete()` method provides an additional idempotency check beyond the checkpoint.

3. **Idempotency via UNIQUE constraints**: Chunk idempotency is guaranteed by `UNIQUE(document_version_id, ordinal)`. Embedding idempotency is guaranteed by `UNIQUE(chunk_id, embedding_model, embedding_version)`. On duplicate INSERT, the noop stages catch the constraint violation and return `performed: false`.

4. **Atomic publication**: The publishing stage runs `transitionDocumentVersionStatus` → `READY` and `setCurrentVersion` inside a single `BEGIN/COMMIT` transaction. If the transaction fails, it ROLLBACKs. A failed stage never transitions the version — the orchestrator leaves the version in `INGESTING` and transitions the job to `RETRY_WAIT` or `FAILED_FINAL`.

5. **Terminal vs. transient errors**: Stages that throw `TerminalJobError` transition the job to `FAILED_FINAL`. Transient errors transition to `RETRY_WAIT`. The consumer's retry policy handles re-delivery.

6. **Migration 004**: The `document_chunks` and `chunk_embeddings` tables were needed for the workflow to demonstrate end-to-end idempotency. While the real chunking/embedding logic is in P2-T05/P2-T06, the table schema matches the committed reference schema in `db/schema.sql`. The migration includes workspace-scoped RLS policies.

7. **Error message safety**: The workflow records safe error codes (`INGESTION_STAGE_ERROR`, `INGESTION_JOB_NOT_FOUND`, etc.) without exposing partial content, raw file data, or internal stack traces.

## Acceptance-Criterion Evidence

### AC1: Workflow resumes safely after worker interruption.

- **Evidence**: "resumes from checkpoint after simulated interruption" test: simulates crash after chunking stage, sets `ingestion_jobs.stage = 'chunking'`. On re-delivery, the handler skips extraction and chunking (both `isComplete()` return true), runs embedding + publishing. Version transitions to READY. Job ends SUCCEEDED.

### AC2: A failed stage never marks a version ready.

- **Evidence**: "failing stage never marks version READY" test: a stage throws `Error('Simulated extraction failure')`. The handler catches it, records the error, transitions job to RETRY_WAIT. The version remains INGESTING (not READY), `isCurrent` remains false. Same for terminal errors — version stays INGESTING, job goes to FAILED_FINAL.

### AC3: Repeated job delivery does not duplicate chunks or embeddings.

- **Evidence**: "is idempotent — re-running the handler does not duplicate artefacts" test: first run creates 1 chunk and 1 embedding. Second run (after resetting job status to QUEUED) still results in exactly 1 chunk and 1 embedding. The noop stages check `isComplete()` before inserting; UNIQUE constraints prevent concurrent duplicates. Publishing stage is a no-op when version is already READY.

### AC4: Final current-version switch is atomic.

- **Evidence**: "publishingStage transitions version to READY and sets as current atomically" test: verifies after publishing stage execution, `version.status === 'READY'`, `version.isCurrent === true`, `version.readyAt` is set. The publishing stage uses a single `BEGIN/COMMIT` transaction — if the transaction fails, it ROLLBACKs leaving the version in INGESTING. The underlying `setCurrentVersion` function atomically supersedes old current versions.

## Remaining Risks or Follow-up Tasks

1. **P2-T04 (parsers)**: Replace `noopExtractionStage` with real parsers for plain text, PDF, DOCX. The stage interface supports pluggable replacement without workflow changes.

2. **P2-T05 (chunking)**: Replace `noopChunkingStage` with deterministic chunking that creates real content, content_hashes, and locators. The existing `document_chunks` table schema is already correct.

3. **P2-T06 (embeddings)**: Replace `noopEmbeddingStage` with a provider-neutral embedding gateway. The existing `chunk_embeddings` table schema and UNIQUE constraint provide idempotency.

4. **Real retry policy**: The workflow currently re-throws errors to the consumer, which applies its own exponential-backoff retry. The ingestion-specific retry policy (`ingestion_jobs.max_attempts`, `next_attempt_at`) is not yet integrated with the consumer's retry loop. Currently the consumer's retry policy (configured via `JobConsumerConfig.maxAttempts`) controls retries independently.

5. **Pipeline versioning**: The noop stages use `noop-${pipelineVersion}` as version strings. Real stages should use semantic versions from the pipeline configuration for cache-busting and compatibility checks.

6. **Index creation**: HNSW/IVFFlat indexes on `chunk_embeddings.embedding` are deferred per the schema comment (line 222 of `db/schema.sql`). Should be created in P2-T07 (retrieval) after corpus measurements.
