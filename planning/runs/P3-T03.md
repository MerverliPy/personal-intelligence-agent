## Design decisions and assumptions

1. **Decoupled evidence type**: `EvidenceItem` is a compiler-owned type, not imported from `@pia/knowledge`. This avoids package dependency coupling and allows evidence from any source (retrieval, tool output, test fixtures).

2. **Untrusted demarcation consistency**: Evidence and user request are wrapped in `<!-- UNTRUSTED -->` / `<!-- /UNTRUSTED -->` markers matching P3-T02's renderer. The marker format is defined locally in the compiler for self-containment.

3. **Token estimation**: Uses `ceil(text.length / 4)` — the standard English heuristic of ~4 characters per token. This is intentionally approximate; exact counting requires model-specific tokenizers and is deferred to when real provider token counts are available (FR-CONV-008).

4. **Compaction strategy**: Three-tier priority: (1) oldest conversation messages dropped first, (2) lowest-scored evidence trimmed, (3) tool definitions dropped as last resort. System rules, mode, prompt, memory, and user request are never dropped.

5. **Message construction**: Sections 1–5 become a single system message. Conversation messages preserve original roles. User request becomes a user message. Tool definitions are included in the system message (not as separate tool messages — that's the P5 gateway's concern).

6. **Sensitivity filtering**: Evidence items with sensitivity above the compiler's `maximumSensitivity` are excluded with reason `SENSITIVITY_POLICY`. The sensitivity order is: PUBLIC < INTERNAL < CONFIDENTIAL < HIGHLY_CONFIDENTIAL < REGULATED < PROHIBITED.

## Security/privacy impact

- Evidence content is always demarcated as untrusted (`<!-- UNTRUSTED -->` markers), preventing prompt-injection attacks from retrieval or tool output.
- User request content is also wrapped in untrusted markers.
- System/policy content (sections 1–4) is always placed BEFORE untrusted sections in the compiled messages — structural guarantee against injection.
- No secrets, credentials, or PII in compiler output.
- Compiler is stateless — no persistence, no caching of compiled contexts.

## Remaining risks or follow-up tasks

- Conversation compaction is OLDEST_FIRST only — summarization-based compaction could be added later.
