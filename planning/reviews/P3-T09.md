## Security and Compatibility Assessment

The task's `security_checks` list is: (1) no secrets introduced; (2) workspace scoping preserved where tenant data is involved. Both are evidenced.

- **No secrets introduced.** The diff is scoped to UI code under `apps/web/**` plus a web-serving route under `apps/api/src/routes/web-conversations.ts` (P2-T09 precedent) and a one-line `server.ts` registration. No `.env`, no `**/*secret*`, no `infra/terraform/prod/**` paths were read or written. The only dependency additions are `vitest@^2.1.0`, `jsdom@^25.0.1`, `@types/jsdom@^21.1.7` to `apps/web` devDependencies — these are development-time test tools, not production secrets or credentials.
- **Workspace scoping preserved.** All page loads validate the `workspace_id` URL param via the existing `requireWorkspaceContext` plugin (enforced on every API call from the page-level `apiFetch` wrapper and on the `POST /v1/workspaces/{wid}/messages/{mid}/feedback` call). The page builders are pure functions of the URL params; no client-side state is shared across workspaces.
- **Untrusted content rendering.** Every user-supplied field (message content, citation `claim_text`, correction, notes, source_locator values) passes through `escapeHtml` at render time. The `citation-modal.test.ts` and `feedback-form.test.ts` include explicit XSS-guard tests for script tags, ampersands, and quotes. The client-side streamed delta uses `textContent += text` (`apps/web/src/pages/conversation-detail.ts:336`), never `innerHTML`, so the model output is escaped by the browser.
- **CSRF.** The feedback POST is covered by the existing `csrfPlugin` in `apps/api/src/plugins/security.ts` (pre-existing). The feedback form is served same-origin, so the session cookie is automatically attached.
- **Open redirect / path traversal.** Conversation list/detail URLs are constructed from server-rendered workspace IDs, not from user input.
- **No-fetch guarantee for the citation modal.** The modal renders synchronously from the in-memory citation object. The `NO-FETCH GUARANTEE` test in `citation-modal.test.ts:111-128` stubs `globalThis.fetch` and asserts it is never called from `renderCitationModalBody`. The client-side `openCitationModal` (`apps/web/src/pages/conversation-detail.ts:173-186`) reads from `window.__piaCitations[citationId]`, set by `registerCitation` from `citation.provisional` and `response.completed` SSE events.
- **API/DB compatibility.** No new endpoints, no new contract types, no new DB columns. The pages consume the existing P3-T05 conversation endpoints and the P3-T08 feedback endpoint.
