## Acceptance criterion review

### AC1: Out-of-bound, absent, unauthorized, deleted, or stale citations are rejected

**PASS.** Directly verified in source and tests:

| Failure mode         | Test                                                           | Status code                     |
| -------------------- | -------------------------------------------------------------- | ------------------------------- |
| Evidence-set absence | Test "should reject citation not in evidence set"              | `INVALID_EVIDENCE_MISSING`      |
| Chunk not found      | Test "should reject citation when chunk not found in DB"       | `INVALID_CHUNK_MISSING`         |
| Cross-workspace      | Test "should reject citation when chunk is in wrong workspace" | `INVALID_CROSS_WORKSPACE`       |
| Version SUPERSEDED   | Test "should reject when version has been SUPERSEDED"          | `INVALID_VERSION_STALE`         |
| Version DELETED      | Test "should reject when version has been DELETED"             | `INVALID_VERSION_STALE`         |
| Version FAILED       | Test "should reject when version is FAILED"                    | `INVALID_VERSION_STALE`         |
| Version not found    | Test "should reject when version is not found"                 | `INVALID_VERSION_STALE`         |
| Non-READY state      | Test "should reject when version is in non-READY state"        | `INVALID_VERSION_STALE`         |
| Page out-of-bounds   | Test "should reject when page exceeds document pageCount"      | `INVALID_LOCATOR_OUT_OF_BOUNDS` |
| Offset out-of-bounds | Tests for startOffset and endOffset exceed characterCount      | `INVALID_LOCATOR_OUT_OF_BOUNDS` |

Implementation in `verifier.ts`: each check function returns structured failure objects with status, reasonCode, and reason. The main loop short-circuits on first failure.

### AC2: Unsupported claims are removed, qualified, or clearly labeled as inference

**PASS.** Primary mechanism is `buildCitations()` (P3-T06, `packages/knowledge/src/citations/builder.ts`) which drops invalid chunk IDs from the evidence set and strips `[infer]`/`[assume]` markers. P3-T07 adds a safety net: the evidence-set membership check (verifier.ts) catches any citation whose chunk was not in the generation evidence set, rejecting it as `INVALID_EVIDENCE_MISSING`.

### AC3: Verifier failure cannot silently produce a normal completed answer

**PASS.** Confirmed in `orchestrator.ts` lines 454-481: when `verificationResult.allValid` is false, the run transitions to FAILED with `errorCode: 'VERIFICATION_FAILED'`, a `run.failed` SSE event is yielded, and `return` prevents execution of the normal completion path. `response.completed` is never emitted.

### AC4: Critical deterministic checks do not rely solely on another model

**PASS.** Confirmed in `verifier.ts`:

- Header comment: "Critical deterministic checks do not rely on another model. All validation is performed via DB queries and in-memory evidence-map lookups."
- Only imports: `pg.Pool` — no LLM, HTTP, or external service imports
- Evidence-set check uses `evidenceMap.has()` (in-memory Map)
- Chunk/version checks use `pool.query()` (PostgreSQL, parameterized)
- Locator check uses in-memory arithmetic only
- Zero network or model calls in the entire verifier
