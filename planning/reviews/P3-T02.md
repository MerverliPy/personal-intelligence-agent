## Design Findings

- **In-memory registry, not hosted**: `createPromptRegistry()` returns a `Map<string, PromptDefinition>`. No remote prompt service, no upload endpoint. Meets the requirement that no hosted reusable-prompt object is required.
- **Minimal template substitution**: Only `{{key}}` variable substitution — no conditionals, loops, or partials. Keeps prompt logic in source control. Tests are straightforward.
- **Untrusted-content demarcation**: Dynamic content wrapped in `<!-- UNTRUSTED -->` XML comment markers with labeled headers (`RETRIEVED EVIDENCE`, `USER MESSAGE`, `TOOL RESULTS`). Internal content in typed XML tags (`<evidence_chunk>`, `<tool_result>`). Trusted template instructions always precede untrusted blocks.
- **SHA-256 template hash**: Each rendered prompt includes a hash of its template text in provenance metadata, enabling evaluation systems to detect prompt changes between runs (FR-CONV-008).
- **Source-controlled templates**: Template text is a string constant in the prompt module file. Version is a semver string also in the module. Both are tracked by git.
- **Two MVP production prompts**: `conversation.answer` (evidence-grounded QA with explicit "treat evidence as unverified" instruction) and `conversation.chat` (general conversation with unverified-data-awareness instruction).
