## Verdict: FAILED_VERIFICATION

### Acceptance Criterion 1: FAIL

> "Every API request and worker job has a correlation identifier."

**Evidence of failure**:

1. `apps/api/src/plugins/request-id.ts:14-19`: The request-id plugin assigns Fastify's built-in `request.id` and echoes it in the `x-request-id` response header. However, it never calls `runWithCorrelation()` from `@pia/observability`. Consequently, `getCurrentCorrelationId()` returns `undefined` during any route handler or plugin hook execution.

2. `apps/api/src/index.ts:40-46`: `runWithCorrelation()` is called only once, wrapping the startup log message. No correlation context exists for incoming HTTP requests.

3. `packages/jobs/src/consumer.ts:189-194`: The consumer creates a `JobContext` with `correlationId: record.id`, but never calls `runWithCorrelation()`. The logger in `@pia/observability` auto-injects correlation IDs from `AsyncLocalStorage`, not from the `JobContext` object. Since `AsyncLocalStorage` is never populated per-job, all handler log entries lack correlation.

4. `apps/worker/src/index.ts:37-88`: `runWithCorrelation()` wraps only the boot sequence. Individual job invocations are uncorrelated.

**Impact**: Log aggregation by correlation ID is impossible. Distributed tracing cannot be anchored to per-request/job identifiers. Audit events cannot be reliably correlated to the originating request.

## Security-specific findings

1. **No inbound ID bounding**: The `x-request-id` header is accepted verbatim without length or character validation. A malicious client could inject a 10MB header value or characters that break log parsing. This is NOT YET an acceptance criterion but is a hardening concern.

2. **Run record naming**: The original run record was filed as `T0-T05.md` instead of `P0-T05.md`. This is a process concern, not a code defect.

## Required remediation

1. Wrap every API request lifecycle in `runWithCorrelation()`.
2. Wrap every job handler execution in `runWithCorrelation()`.
3. Add bounded validation for externally-supplied correlation identifiers.
4. Add tests proving per-request and per-job correlation context isolation.
5. Correct run record naming from `T0-T05.md` to `P0-T05.md`.
