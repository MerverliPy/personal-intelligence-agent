## Limitations and Remaining Risks

- **Deterministic scoring is not a substitute for LLM-based grading.**
  P3-T10 catches fabricated sources, refusal behavior, cross-tenant
  leakage, and prompt-injection directive language, but cannot catch
  nuanced quality issues. P6-T01 is the planned follow-up.
- **Groundedness heuristic is a strict word-overlap check.** Paraphrased
  claims will score below the 50% threshold; the P3-T10 dataset is
  calibrated to direct or near-direct quotes. P6-T01 will add
  semantic-overlap scoring.
- **Provider-failure error sanitization** is a documented P4+ follow-up
  (orchestrator currently passes raw provider error text through,
  truncated to 200 chars).
- **P3-T08 cross-tenant insert fix** is a P4 follow-up. The test
  `p3-t08-cross-tenant-insert.test.ts` documents the gap as a
  regression sentinel.
- **Test database scope.** P3-T10 creates `pia_e2e_test` and
  `pia_security_test`, isolated disposable DBs. A future cleanup task
  could remove them on CI teardown.
- **Vitest config limitations.** The root `.eslintrc.json` does not
  list `test/e2e/**` or `test/security/**` in `parserOptions.project`,
  so `pnpm exec eslint test/...` reports parsing errors. The monorepo
  `pnpm lint` (which lints only packages and apps) passes. The test
  files are validated by vitest (TypeScript-direct) and `pnpm typecheck`
  (which doesn't see them because the root `tsconfig.json` is
  references-only). A follow-up could add `test/tsconfig.json` and
  update `.eslintrc.json`.
- **P3-T10 is a large task.** ~14 new files + 3 modified files across
  5 directories. Cross-file regression risk is mitigated by the type
  system and the test suite.
