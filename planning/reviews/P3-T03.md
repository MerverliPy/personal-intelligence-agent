## Design Findings

- **Decoupled evidence type**: `EvidenceItem` is compiler-owned — no dependency on `@pia/knowledge`. Consumers map `RetrievalResult` → `EvidenceItem`. Enables testing with simple objects.
- **Deterministic assembly**: `CONTEXT_SECTION_ORDER` array drives section iteration. Items within each section are stable-sorted (evidence by score desc, conversation by index). Same input always produces identical output.
- **Untrusted demarcation**: Evidence and user request wrapped in `<!-- UNTRUSTED -->` markers matching P3-T02's renderer. Markers defined locally in compiler for self-containment. Structural guarantee: system sections (1–4) always precede untrusted sections (5, 7) in output.
- **Three-tier compaction**: `enforceBudget()` applies conversation truncation → evidence trimming → tool dropping, each with configurable minimum retention. `budgetExhausted` reflects unresolved overflow (e.g., when system content alone exceeds budget).
- **Message construction**: System sections merged into single system message. Conversation messages preserve original roles. User request as user message. Clean, provider-neutral output ready for P3-T01 `ModelGateway.generate()`.
- **Sensitivity gating**: `SENSITIVITY_ORDER` lookup + `isAboveSensitivity()` function enables policy-checked evidence inclusion when `maximumSensitivity` is set. Excluded items tagged `SENSITIVITY_POLICY`.
