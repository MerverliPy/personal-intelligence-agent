## Security-specific findings

- **Embedding API key**: Stored as `Redacted` in config layer; never logged. Environment variable `EMBEDDING_API_KEY` handled by config, not the adapter.
- **Content sensitivity**: Embedding stage operates on already-authorized document chunks; upstream ingestion workflow handles authorization.
- **Provider isolation**: Fake provider runs locally without network access (`node:crypto`). No third-party SDK credentials in process.
- **Version isolation**: Different `embedding_version` values create separate DB rows, preventing silent mixing of vectors from different models/dimensions.
- **No raw content in logs**: Structured logging excludes sensitive fields per observability redaction rules.

## Design Findings

- Provider-neutral interface follows dependency-inversion pattern (same as `ScanProvider`).
- Fake provider uses SHA-256 for deterministic, L2-normalized vectors — suitable for dev, CI, and deterministic testing.
- Batch processing with configurable batch size (default 20).
- Transient provider errors propagate for retry; dimension mismatches and constraint violations throw `TerminalJobError`.
